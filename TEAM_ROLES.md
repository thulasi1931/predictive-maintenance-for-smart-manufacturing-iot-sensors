# Cognizant Hackathon Team Roles (8 Members)

Use your names in place of Member 1–8 before submission. Each person should own a visible part of the demonstration and be ready to answer questions about it.

| Member | Assigned role | Review responsibility |
|---|---|---|
| Member 1 | Project lead and presenter | Problem statement, business value, architecture, and final demo flow. |
| Member 2 | Data and ML engineer | AI4I dataset, feature engineering, class imbalance, metrics, and model limitations. |
| Member 3 | Forecasting engineer | Telemetry trend forecast, safe operating bounds, and how forecast differs from failure classification. |
| Member 4 | Backend/API engineer | Flask endpoints, validation, prediction service, and alert logic. |
| Member 5 | Frontend/UX engineer | React dashboard, accessibility, user journey, and responsive interface. |
| Member 6 | IoT and simulation engineer | Sensor fields, live simulator, telemetry flow, and real-device integration roadmap. |
| Member 7 | Maintenance workflow engineer | Alerts, work orders, technician assignment, completion tracking, and estimated downtime cost. |
| Member 8 | QA, deployment, and documentation engineer | Test evidence, GitHub/Render deployment, README, risks, and final submission checklist. |

## Suggested presentation sequence

1. Member 1: introduce the downtime problem and value proposition (1 minute).
2. Member 6: show sensor data arriving through the simulator (1 minute).
3. Member 2: explain the prediction model and fair evaluation (1 minute).
4. Member 5: demonstrate the dashboard and risk result (1 minute).
5. Member 3: demonstrate the bounded next-reading trend forecast (45 seconds).
6. Member 7: create and complete a work order (45 seconds).
7. Member 4: explain API, alerting, and data flow (45 seconds).
8. Member 8: show test/deployment evidence; Member 1 closes with impact and roadmap (45 seconds).
